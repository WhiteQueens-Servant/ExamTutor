# DeepTutor 系统全貌 — 全局视角

> 本文档解决一个核心困惑：**每个组件都能理解，但整体却看不懂**。
> 通过讲清楚"一个用户请求的完整生命周期"，让你理解各组件如何协作。

---

## 一、为什么会有"组件都懂，整体不懂"的感觉？

### 1.1 根本原因

我们一直在讲**"组件内部怎么工作"**，但没有讲**"一个请求从输入到输出的完整旅程"**。

**比喻**：
- 你知道发动机怎么工作
- 你知道变速箱怎么工作
- 你知道方向盘怎么工作
- 但你不知道**一辆车怎么从A点开到B点**

**Deeptutor 的问题**：
- 每个组件都有完整的闭环（输入→处理→输出）
- 但组件之间的**协作关系**不够清晰
- 缺少一个**全局视角**来讲清楚"一个请求的完整生命周期"

### 1.2 解决方案

本文档将通过**一个完整的例子**，讲清楚：
1. 用户输入一个问题，系统做了什么？
2. 哪些组件参与了？
3. 它们怎么协作的？
4. 最终怎么返回给用户的？

**期望输出**：系统给出一个结构化的解释，包含定义、原理、应用。

### 3.3 涉及组件总结

| 阶段 | 涉及组件 | 做了什么 |
|------|---------|---------|
| 阶段 1 | CLI / WebSocket | 接收用户输入，转为 UnifiedContext |
| 阶段 2 | ChatOrchestrator | 分析请求，路由到 Chat 能力 |
| 阶段 3 | Chat Pipeline + PromptManager + LoopHost + LabelProtocol | 初始化能力，加载 prompt，配置工具和标签 |
| 阶段 4 | Agentic Loop + labeled_step + LLM + tool_dispatch + RAG | 循环执行：思考→调用工具→返回结果 |
| 阶段 5 | Chat Pipeline | 处理结果，返回给用户 |

## 四、组件协作关系详解

### 4.1 PromptManager 的角色

**什么时候被调用**：阶段 3，能力初始化时

**做了什么**：
- 加载 chat/prompt.yaml
- 提取 system prompt 和 user template
- 返回给 Chat Pipeline

**与其他组件的关系**：
- 被 Chat Pipeline 调用
- 返回 prompt 给 Chat Pipeline
- Chat Pipeline 将 prompt 放入 messages，传给 Agentic Loop

### 4.2 Agentic Loop 的角色

**什么时候被调用**：阶段 4，能力执行时

**做了什么**：
- 驱动循环：调用 LLM → 验证标签 → 分发处理
- 管理上下文：维护 messages 列表
- 协调工具：调用 tool_dispatch 执行工具

**与其他组件的关系**：
- 被 Chat Pipeline 调用
- 调用 labeled_step 调用 LLM
- 调用 tool_dispatch 执行工具
- 返回 LoopOutcome 给 Chat Pipeline

### 4.3 RAG Pipeline 的角色

**什么时候被调用**：阶段 4，第 2 轮迭代时

**做了什么**：
- 接收 search_knowledge 调用
- 检索知识库
- 返回相关文档

**与其他组件的关系**：
- 被 tool_dispatch 调用
- 返回结果给 tool_dispatch
- tool_dispatch 将结果添加到 messages

### 4.4 PromptManager 与 Agentic Loop 的关系

**直接关系**：无直接调用关系

**间接关系**：
- PromptManager 加载 prompt
- Chat Pipeline 将 prompt 放入 messages
- Agentic Loop 使用 messages 调用 LLM

**比喻**：
- PromptManager 是"写菜单的人"
- Agentic Loop 是"按菜单做菜的厨师"
- 它们通过"菜单"（messages）间接协作

## 五、面试话术：如何回答"系统怎么工作的"

### 5.1 开场白

"DeepTutor 是一个 Agent-Native 的个性化学习伴侣系统。当用户输入一个问题时，系统会经过五个阶段：接收请求、路由选择、能力初始化、循环执行、结果返回。"

### 5.2 详细流程

"以用户问'什么是傅里叶变换'为例：

1. **接收请求**：CLI 接收用户输入，转为 UnifiedContext
2. **路由选择**：ChatOrchestrator 分析请求类型，路由到 Chat 能力
3. **能力初始化**：Chat Pipeline 加载 prompt（通过 PromptManager），配置工具和标签
4. **循环执行**：Agentic Loop 驱动循环，先思考（THINK），再调用 RAG 检索知识库（TOOL），最后给出答案（FINISH）
5. **结果返回**：Chat Pipeline 处理结果，返回给用户"

### 5.3 组件协作

"在这个过程中，各组件协作关系是：
- **PromptManager**：提供 prompt 模板
- **Agentic Loop**：驱动整个推理过程
- **RAG Pipeline**：提供知识检索能力
- **LLM**：提供推理能力

它们通过**消息列表**（messages）间接协作，每个组件只关心自己的职责，通过统一的接口交互。"

## 六、总结

### 6.1 核心理解

1. **系统是分层的**：入口层 → 路由层 → 能力层 → 工具层 → 基础层
2. **请求是有生命周期的**：接收 → 路由 → 初始化 → 执行 → 返回
3. **组件是协作的**：每个组件只关心自己的职责，通过接口交互
4. **Agentic Loop 是核心**：它驱动整个推理过程，协调各组件

### 6.2 面试关键点

1. **不要只讲组件**：要讲"一个请求的完整旅程"
2. **不要只讲技术**：要讲"解决了什么问题"
3. **不要只讲细节**：要讲"整体架构和协作关系"

### 6.3 记忆口诀

**"五阶段、四层、三协作"**：
- 五阶段：接收 → 路由 → 初始化 → 执行 → 返回
- 四层：入口层 → 路由层 → 能力层 → 工具层 → 基础层
- 三协作：PromptManager 提供 prompt，Agentic Loop 驱动循环，RAG 提供知识
