# 两层插件架构详解 — 面试解读

> 本文档从面试角度解读 DeepTutor 的两层插件架构（Tools + Capabilities），帮助你在面试中清晰表达技术细节。

---

## 一、系统架构概览

### 1.1 核心概念

DeepTutor 采用**两层插件架构**：

| 层次 | 名称 | 职责 | 示例 |
|------|------|------|------|
| **L1** | Tools（工具） | 单功能工具，LLM 按需选取 | RAG、Web Search、Code Execution |
| **L2** | Capabilities（能力） | 多步骤管道，完整的任务流程 | Deep Solve、Deep Question、Exam Sprint |

### 1.2 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    用户请求                                   │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                    ChatOrchestrator                          │
│  • 统一入口                                                  │
│  • 路由到 Capability 或 Tool                                 │
│  • 管理会话上下文                                            │
└─────────────────────────────────────────────────────────────┘
                           │
           ┌───────────────┴───────────────┐
           ▼                               ▼
┌─────────────────────────┐    ┌─────────────────────────┐
│    L2: Capabilities     │    │     L1: Tools            │
│  ┌───────────────────┐  │    │  ┌───────────────────┐  │
│  │   Deep Solve      │  │    │  │       RAG         │  │
│  │   Deep Question   │  │    │  │   Web Search      │  │
│  │   Exam Sprint     │  │    │  │  Code Execution   │  │
│  │   Visualize       │  │    │  │     Reason        │  │
│  └───────────────────┘  │    │  └───────────────────┘  │
└─────────────────────────┘    └─────────────────────────┘
           │                               │
           │    ┌─────────────────┐        │
           └────┤   ToolRegistry  ├────────┘
                │   (L1 注册中心)  │
                └─────────────────┘
```

### 1.3 核心组件职责

| 组件 | 职责 | 关键类/协议 |
|------|------|------------|
| **BaseTool** | 工具基类 | `BaseTool`, `ToolDefinition` |
| **BaseCapability** | 能力基类 | `BaseCapability`, `CapabilityManifest` |
| **ToolRegistry** | 工具注册中心 | `ToolRegistry` |
| **CapabilityRegistry** | 能力注册中心 | `CapabilityRegistry` |
| **ChatOrchestrator** | 统一路由 | `ChatOrchestrator` |

## 二、面试题与参考答案

### 面试题 1：请描述两层插件架构的设计理念

**参考答案：**

两层插件架构的设计理念是**关注点分离**：

| 层次 | 设计理念 | 适用场景 |
|------|---------|---------|
| **L1 Tools** | 单一职责，原子操作 | 取一个事实、跑一次计算、做一次检索 |
| **L2 Capabilities** | 多步骤流程，完整任务 | 解题、出题、做研究、生成可视化 |

**设计优势：**

1. **灵活性**：用户可以自由组合 Tools
2. **可扩展**：新 Tool 或 Capability 只需实现接口
3. **可复用**：Tools 可以被多个 Capabilities 调用
4. **可测试**：每个 Tool/Capability 独立测试

**面试加分点：**
- **分层解耦**：L1 和 L2 职责清晰
- **插件化**：支持动态注册和卸载
- **组合性**：Tools 可以被 Capabilities 调用

### 面试题 2：Tool 和 Capability 的区别是什么？

**参考答案：**

| 维度 | Tool（工具） | Capability（能力） |
|------|-------------|-------------------|
| **粒度** | 单功能 | 多步骤流程 |
| **调用方式** | LLM 按需选取 | 用户选择或自动路由 |
| **上下文** | 无状态 | 有状态（会话上下文） |
| **输出** | 单次结果 | 多阶段输出 |
| **示例** | RAG、Web Search | Deep Solve、Exam Sprint |

**Tool 示例（RAG）：**

```python
class RAGTool(BaseTool):
    definition = ToolDefinition(
        name="rag",
        description="Search knowledge base for relevant information",
        parameters=[
            ToolParameter(name="query", type="string", description="Search query"),
            ToolParameter(name="kb_name", type="string", description="Knowledge base name"),
        ],
    )
    
    async def execute(self, query: str, kb_name: str) -> dict:
        # 单次检索，返回结果
        return await rag_search(query=query, kb_name=kb_name)
```

**Capability 示例（Deep Solve）：**

```python
class DeepSolveCapability(BaseCapability):
    manifest = CapabilityManifest(
        name="deep_solve",
        description="Multi-step problem solving",
        stages=["planning", "reasoning", "writing"],
        tools_used=["rag", "web_search", "code_execution"],
    )
    
    async def run(self, context: UnifiedContext, stream: StreamBus):
        # 多阶段流程
        async with stream.stage("planning"):
            plan = await self._plan(context)
        
        async with stream.stage("reasoning"):
            for step in plan.steps:
                await self._solve_step(step)
        
        async with stream.stage("writing"):
            await self._synthesize(plan)
```

**面试加分点：**
- **粒度差异**：Tool 是原子操作，Capability 是流程
- **状态差异**：Tool 无状态，Capability 有状态
- **调用差异**：Tool 由 LLM 选取，Capability 由用户选择

### 面试题 3：如何实现 Tool 的注册和发现？

**参考答案：**

Tool 的注册和发现采用**注册中心模式**：

**注册流程：**

```python
# 1. 定义 Tool
class RAGTool(BaseTool):
    definition = ToolDefinition(
        name="rag",
        description="Search knowledge base",
        parameters=[...],
    )
    
    async def execute(self, **kwargs):
        ...

# 2. 注册到 Registry
tool_registry = ToolRegistry()
tool_registry.register(RAGTool())

# 3. LLM 发现可用 Tools
tools = tool_registry.get_tool_definitions()
# 返回 OpenAI function-calling 格式的 schema
```

**发现机制：**

```python
class ToolRegistry:
    def __init__(self):
        self._tools: dict[str, BaseTool] = {}
    
    def register(self, tool: BaseTool):
        """注册工具"""
        self._tools[tool.definition.name] = tool
    
    def get_tool_definitions(self) -> list[dict]:
        """获取所有工具的 schema（供 LLM 使用）"""
        return [tool.definition.to_openai_schema() for tool in self._tools.values()]
    
    async def execute(self, tool_name: str, **kwargs) -> dict:
        """执行工具"""
        tool = self._tools.get(tool_name)
        if tool is None:
            raise ValueError(f"Tool '{tool_name}' not found")
        return await tool.execute(**kwargs)
```

**面试加分点：**
- **动态注册**：运行时可以注册新工具
- **Schema 生成**：自动生成 OpenAI function-calling 格式
- **统一执行**：通过 Registry 统一执行工具

### 面试题 4：如何实现 Capability 的路由？

**参考答案：**

Capability 的路由采用**自动路由 + 手动选择**两种方式：

**自动路由（Auto Mode）：**

```python
class AutoCapability(BaseCapability):
    """自动路由到最合适的 Capability"""
    
    async def run(self, context, stream):
        # 1. 分析用户请求
        analysis = await self._analyze_request(context.user_message)
        
        # 2. 选择最合适的 Capability
        capability = self._select_capability(analysis)
        
        # 3. 委托执行
        await capability.run(context, stream)
```

**手动选择（用户指定）：**

```python
# 用户在聊天界面选择 Deep Solve
context = UnifiedContext(
    user_message="求解 x^2 = 4",
    active_capability="deep_solve",  # 用户指定
)

# ChatOrchestrator 路由到 DeepSolveCapability
capability = capability_registry.get("deep_solve")
await capability.run(context, stream)
```

**路由策略：**

| 策略 | 说明 | 示例 |
|------|------|------|
| **关键词匹配** | 基于关键词路由 | "求解" → Deep Solve |
| **意图识别** | 基于意图路由 | "出题" → Deep Question |
| **用户选择** | 用户手动选择 | 用户点击 "Deep Solve" |

**面试加分点：**
- **双重路由**：支持自动和手动
- **意图识别**：基于用户请求智能路由
- **可扩展**：新 Capability 只需注册即可

### 面试题 5：Tool 和 Capability 如何协作？

**参考答案：**

Tool 和 Capability 采用**组合模式**协作：

**协作流程：**

```
1. 用户发起请求
2. ChatOrchestrator 路由到 Capability
3. Capability 执行多步骤流程
4. 每个步骤可以调用 Tools
5. Tools 返回结果，继续流程
```

**示例（Deep Solve）：**

```python
class DeepSolveCapability(BaseCapability):
    async def run(self, context, stream):
        # Phase 1: 规划
        plan = await self._plan(context)
        
        # Phase 2: 执行（每步可能调用 Tools）
        for step in plan.steps:
            if step.needs_rag:
                # 调用 RAG Tool
                rag_result = await self._tool_registry.execute(
                    "rag", query=step.query, kb_name=context.kb_name
                )
                step.context = rag_result["answer"]
            
            if step.needs_web_search:
                # 调用 Web Search Tool
                search_result = await self._tool_registry.execute(
                    "web_search", query=step.query
                )
                step.context = search_result["results"]
            
            # 执行步骤
            await self._execute_step(step)
        
        # Phase 3: 综合
        await self._synthesize(plan)
```

**协作优势：**

| 优势 | 说明 |
|------|------|
| **复用** | Tools 可以被多个 Capabilities 调用 |
| **解耦** | Capability 不需要知道 Tool 的实现细节 |
| **可测试** | Tools 和 Capabilities 独立测试 |

**面试加分点：**
- **组合模式**：Capability 组合 Tools 完成复杂任务
- **依赖注入**：ToolRegistry 作为依赖注入
- **松耦合**：Capability 不直接依赖 Tool 实现

### 面试题 6：两层架构的优势是什么？

**参考答案：**

两层架构相比单层架构有以下优势：

| 优势 | 说明 |
|------|------|
| **灵活性** | 用户可以自由组合 Tools |
| **可扩展** | 新 Tool 或 Capability 只需实现接口 |
| **可复用** | Tools 可以被多个 Capabilities 调用 |
| **可测试** | 每个 Tool/Capability 独立测试 |
| **可维护** | 职责清晰，易于维护 |

**与单层架构对比：**

| 方面 | 单层架构 | 两层架构 |
|------|---------|---------|
| 粒度 | 混合 | 清晰分离 |
| 复用 | 困难 | 容易 |
| 扩展 | 修改现有代码 | 新增实现 |
| 测试 | 集成测试 | 独立测试 |

**面试加分点：**
- **关注点分离**：L1 和 L2 职责清晰
- **插件化**：支持动态注册和卸载
- **组合性**：Tools 可以被 Capabilities 调用

## 四、面试话术模板

### 开场白

"我负责的 DeepTutor 采用两层插件架构，L1 Tools 提供原子操作，L2 Capabilities 提供多步骤流程，通过注册中心统一管理，支持动态组合和扩展。"

### 技术细节

"在 L1 层，Tools 采用单一职责设计，每个 Tool 只做一件事；在 L2 层，Capabilities 组合多个 Tools 完成复杂任务；在注册中心，Tools 和 Capabilities 动态注册，自动生成 schema 供 LLM 使用。"

### 亮点总结

"这个架构的亮点在于：一是两层分离职责清晰；二是插件化支持动态扩展；三是组合性支持灵活搭配。"
